# 02 — Semantic Layers for Reliable LLM-Powered Data Analytics

- **arXiv**: 2604.25149
- **Authors**: Michael Rumiantsau, Ivan Fokeev (Cube — team@cube.dev)
- **Axes**: data_kind = structured; layer = view_semantic_layer (primary), catalog_metadata (secondary)

## Claims

- Adding a ~4 KB hand-authored markdown semantic-layer document to the prompt raises first-shot analytical accuracy by +17.2 to +23.2 pp across all three models — Opus 4.7 50.5%→67.7%, Sonnet 4.6 46.5%→68.7%, GPT-5.4 45.5%→68.7% — each paired exact McNemar p ≤ 0.0015 [2: §5.1, Table 1].
- With the document, the three models are statistically indistinguishable (67.7–68.7%); without it they are also indistinguishable (45.5–50.5%) [2: §5.1].
- All nine cross-cluster pairwise comparisons are significant at p < 0.01; all three intra-cluster comparisons within the semantic-layer cluster are ns (p ≥ 0.79) and within the raw cluster are ns (p ≥ 0.42) [2: §5.2, Table 2].
- The presence or absence of the semantic-layer document accounts for essentially all significant pairwise variance on the benchmark; model choice within tier does not [2: §5.2].
- Accuracy failures and confident hallucinations are two views of one underlying failure: the model is forced to infer business semantics the schema does not encode [2: §1, §2.1].
- Schema-linking and business-logic errors account for over 80% of execution failures in LLM-generated SQL [2: §1, §6.1 (citing Shen et al. 2025)].
- The semantic-layer effect is structural — a property of how the task is framed, not of model capability — so a smaller model with the document consistently outperforms a larger model without it [2: §6.1].
- A semantic layer converts the dominant text-to-SQL error class from open-ended inference into constrained lookup [2: §3.1, §7].
- Wins (semantic passes, raw fails) concentrate in five categories: multi-fact-table disambiguation, snapshot-vs-flow (raw condition sums daily inventory snapshots, producing values ~1000× too large), calculated-metric formulas, implicit defaults (sentinel `PromotionKey=1`, string-valued booleans), and time anchoring (raw uses `today()` against a dataset ending 2009-12-31, returning empty results) [2: §5.4].
- The residual ~30% of semantic-condition failures concentrate on patterns not encoded in the document — percentiles, correlation, standard deviation, ABC-classification, threshold ranking, complex multi-CTE pivots — and are fixable by extending the document with named measures rather than by changing the mechanism [2: §5.4, §6.4].
- In steady-state production, prompt caching amortizes the schema-plus-document prefix so the marginal cost of the semantic document is effectively zero; Sonnet 4.6 + Sem matches Opus + Sem accuracy at ~28% fewer input tokens [2: §5.3].

## Assumptions

- The semantic-layer document is authoritative and was hand-authored by an analyst who had seen the dataset (but not the final benchmark questions); document quality and coverage bound the effect, and a truly blind document might encode less of the right knowledge [2: §4.2, §6.5].
- Single-shot, no tools, no iteration, no retries, fixed "medium" reasoning effort in both conditions — taken to represent the deployment a team gets by pointing a frontier model at its warehouse [2: §4.2, §4.3].
- The context-form benefit is treated as a lower bound on what a deterministic runtime-form semantic layer (compiler-enforced) could provide [2: §3.2, §6.2].
- The analytical LLM-judge verdict (row-level match, relaxed for benign reformulations) is taken as a faithful proxy for how a human BI analyst would judge correctness [2: §4.4].
- The judge (claude-sonnet-4-6) shares a model family with two of three tested systems; the paired design is assumed to equalize any self-preference bias across conditions rather than inflate the delta [2: §4.4, §6.5].

## Method

- **Paired single-shot benchmark.** 100 NL questions, balanced 20-per-tier across five difficulty levels (simple → medium → complex → advanced → expert), over the Cleaned Contoso Retail Dataset (25 tables, sales 2007–2009) loaded into ClickHouse under the `retail` schema. Each question carries a reference `expected_sql` for ground truth. q33 is excluded (its reference query exceeds ClickHouse's memory quota), leaving n = 99 across all configs [2: §4.1, §5.1].
- **Two conditions differing in exactly one respect.** *Raw*: question + full CREATE-TABLE DDL of all 25 tables, one SQL string emitted and executed, no tools/iteration/retries. *Semantic-layer*: identical, plus a single ~4 KB markdown document (8,969 chars, ~2,200 tokens) covering fact-table selection rules, measure formulas (gross margin, return rate, AOV, inventory turnover, same-store growth, recency segments), dimensional hierarchies, data conventions/quirks (string-booleans, snapshot semantics, sentinel keys), implicit defaults, and explicit disambiguation rules. The document is advisory NL prose, not code, and is not enforced [2: §4.2].
- **6 configurations**: 3 models (Claude Opus 4.7 via `claude -p`, Claude Sonnet 4.6 via `claude -p`, GPT-5.4 via `codex exec`) × 2 conditions, all 100 questions per config [2: §4.3].
- **Grading.** Execute `expected_sql` for ground-truth rows; execute each config's SQL for candidate rows; an LLM judge (claude-sonnet-4-6, JSON-schema-enforced output, single parse retry) returns pass / fail / excluded per (question, config). The judge is blind to which config produced a candidate and is not shown the document. Two verdicts: *strict* (row-level match, ignoring column order and sub-1% numeric drift) and *analytical* (strict relaxed to credit grouped breakdowns aggregating to the reference scalar, unit equivalences, null-category rows). Analytical is the primary metric [2: §4.4].
- **Statistics.** Wilson 95% CI per config; two-sided exact McNemar on paired binary outcomes, reported as discordant counts b/c (first passes / second fails) [2: §4.4].

## Eval

- **Measured**: analytical pass rate (primary), strict pass rate (secondary check), paired per-model ΔPR (primary effect size), McNemar discordant counts b/c + two-sided exact p, mean wall-clock latency, mean input/output token counts [2: §4.6].
- **Baseline**: the raw schema-only condition; each model is its own paired control. There is no external SOTA comparator — the design deliberately isolates the document's effect from model/family/prompt/tool confounds [2: §4, §4.2].
- **Data / metrics**: 99 Contoso retail questions in ClickHouse; binary row-level agreement with reference rows under the two verdict rubrics.
- **Headline numbers** (analytical, Table 1): raw 45.5–50.5% → semantic 67.7–68.7%; ΔPR +17.2 / +22.2 / +23.2 pp for Opus / Sonnet / GPT-5.4; all p ≤ 0.0015. Pairwise matrix (Table 2): two clean clusters, every cross-cluster comparison significant (mostly p < 0.001), no intra-cluster comparison significant [2: §5.1–5.2].
- **External corroboration synthesized** (not re-run): BIRD +20.01 pp from one sentence of evidence; Sequeda et al. 16.7%→54.2% with an ontology; Bayer/JAMIA +70 pp on pharmacovigilance; dbt Labs 84.1%→100% on a modeled layer; Luo et al. clinical QA 37%→98% with ontology-grounded GraphRAG [2: §2.6, §2.7, §5.1, §7].

## Weaknesses

- **Co-designed document and benchmark, same team.** The five "win" categories (string-booleans, sentinel keys, snapshot semantics, the 2009-12-31 anchor, customer-vs-store geography) are exactly the convention list the document enumerates *and* the conventions the benchmark questions were deliberately built around [2: §4.1, §4.2, §5.4]. The +20 pp may partly measure "the document hands over the answers to the trick questions this benchmark intentionally included," not generic business-semantics transfer. The paper concedes only the milder "doc author had not seen final questions" version [2: §6.5]; it does not flag that questions and document share one authoring team (Cube).
- **Vendor study leaning on vendor corroboration.** The authors are Cube, which sells a semantic-layer runtime; the "single largest lever" conclusion is product-aligned, and several "cross-vendor consistency" sources (Snowflake, AtScale, Databricks, Tiger, dbt) are themselves vendor-published. The paper labels them "directional" yet still folds them into the structural-generalization claim [2: §2.7, §7].
- **The thesis-relevant artifact (runtime form) is untested, and a damaging negative result is buried.** Only the advisory context form is measured; the runtime/view form that would absorb physical churn is left to future work [2: §6.2]. More pointedly, §6.5 reports in a single sentence — with no data — that an internal agentic-tool-use system with equivalent semantic knowledge did *not* beat the schema-only baseline, implying search-based metadata discovery underperforms all-context-in-prompt for one-shot accuracy; a result directly adverse to agentic data access is disclosed without evidence [2: §6.5].
- **No staleness / wrong-document test.** The whole premise is an *authoritative* static document, but there is no condition with a partial, outdated, or incorrect document — even though the paper itself cites BIRD audits finding 7–10% of evidence annotations wrong [2: §2.6]. The production concern of whether the document stays correct as the warehouse evolves is entirely unaddressed.
- **Scale mismatch between motivation and validation.** The motivation rests on enterprise schemas of hundreds-to-thousands of columns where models collapse (Spider 2.0, BEAVER) [2: §2.3], but validation is a 25-table dataset with a 4 KB document. Whether a hand-authored document remains feasible or maintainable at that enterprise scale — the regime that motivates the work — is never examined.
